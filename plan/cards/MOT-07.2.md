Implement `ros2_ws/src/crackvision_motion/crackvision_motion/tool_fk.py`. It is the retimer's FK and must stay ROS-free under /usr/bin/python3.

API (refine names to what §16 says):
- `ToolFKError(ValueError)`;
- `load_tool_chain(urdf_path, end_effector_path) -> ToolChain` with `.joint_names` (joint1..6), `.urdf_sha256` and `.end_effector_sha256`;
- `ToolChain.tool_pose(q) -> 4x4`;
- `ToolChain.tool_positions(Q: (N,6)) -> (N,3)`.

Implementation details:
- **URDF.** Walk the URDF from gripper_link to base_link the same way `crackvision.kinematics.load_chain` does: rpy fixed-axis `Rz·Ry·Rx`, revolute rotation about the normalised axis. Use `crackvision_description.end_effector.rpy_to_matrix`/`transform`/`load_config` for the tool block. `parent_link` must be gripper_link; otherwise raise.
- **Defaults** are resolved by callers (the CLI, MOT-07.5). The module itself takes explicit paths.
- **Fixture.** `make_fk_reference.py` runs under `./env.sh python`. It imports `crackvision.kinematics` and writes `fk_reference.json` with: urdf path+sha, end_effector path+sha, a seed, configs, and tool_tip `position_m` + `quat_xyzw` from `load_chain().fk(q) @ T_gripper_link_tool_tip`. With `--check` it recomputes and compares, writing nothing. The fixture uses the repo's own `presentation/sim` URDF and `config/robot/end_effector.yaml`.
- **Tests** use `conftest.py`'s sys.path setup (no colcon build needed).
