## Re-specified 2026-09-30 (technical-lead recovery, ADR-014)
Attempt 00094 was blocked as an 'operator decision', but the cause was a frame error, not a requirement: the
standoffs 0.01/0.04 m were always tool-TIP clearances (0.04 m is the presentation's STANDOFF_APPROACH_M, whose IK
tip was gripper_link = the closed-finger tip) and had been applied to gripper_tcp, the grasp centre 44.3 mm
proximal to the tip, so the fingers were 34/4 mm inside the surface. (Earlier card text said gripper_link was
44.3 mm *behind* gripper_tcp; that was backwards.) The grid-wide thin slab also ran under the base and hit
link2 at surface_z >= ~0.10, and there was no table. MOT-04.6 fixed the model and GEOM-10 added the tool_tip,
the wrist D405 and its collision proxies; config/motion/reachability.yaml now uses them. A coarse feasibility
probe by the recovery session (0.06 m grid) found 599/910 targets reachable, a feasible 0.20 m placement near
(0.29, 0) on the table, 200/200 half-step verification and reachable camera views - so a feasible result is
expected, but this card must produce and report the real full-resolution one, whatever it is.

## Steps
1. `bash scripts/ros/build_ws.sh`.
2. Full sweep, in the background, watching the progress log (~3780 targets, ~0.4 s each => ~25-30 min):
   `bash scripts/ros/run_reachability.sh --reachability-config config/motion/reachability.yaml --out data/motion/reachability_map.json --max-duration-s 3000`
   If it would not finish (complete:false), coarsen only the grid step or trim clearly unreachable y extents,
   record the change and the reason in the YAML comment and the doc, and re-run. Do NOT change ik_link,
   standoffs, orientation, IK tolerance or any collision setting. Leave the map in data/motion/ (git-ignored)
   and record its sha256.
3. `ros2 run crackvision_motion recommend_placement --map data/motion/reachability_map.json --out config/motion/specimen_placement.yaml --emit-verify-config config/motion/placement_verify.yaml --emit-view-config config/motion/view_verify.yaml`
   (inside env_ros.sh + overlay). Exit 1 (infeasible) is a legitimate result: then write the doc honestly and stop.
4. Run the placement-verify and view-verify acceptance commands yourself and record the results.
5. Per-surface_z best placements for the doc: e.g. a throwaway system-python3 snippet calling
   crackvision_motion.placement.score_candidates on the loaded map restricted to one surface_z; record the snippet.
6. scripts/motion/plot_reachability.py already exists (attempt 00094): keep its INTERFACES §0 behaviour; add the
   task frame (map robot.ik_link) and collision model (map grid.surface_collision.model + grid.environment) to the
   title; <=150 dpi, PNG <= 400 KB; `--dry-run` validates inputs and writes nothing.
7. Rewrite docs/motion/REACHABILITY.md: Purpose; Method (ADR-014 task frames, tool-tip clearances, specimen_block +
   base keep-out + table, FK re-check, prefilter); Commands; Results (table per surface_z, figure, recommendation +
   alternatives, best placement per surface_z); Independent verification + camera view check; Why the previous run
   found nothing; Comparison with TECHNICAL_APPROACH §2.5; Caveats + re-run triggers; Handoff to MOT-10/MOT-03 (the
   specimen object in config/scene/scene.yaml takes its nominal pose from this file until MOT-10 measures it).

Commit only files in scope. Never commit data/ or logs/.
