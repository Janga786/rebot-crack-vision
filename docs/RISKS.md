# RISKS.md — risk register

Scored **Likelihood** × **Impact** ∈ {Low, Medium, High}. "Owner" is the task card that must
demonstrably mitigate the risk (its acceptance criteria are where the mitigation is proven).

| ID | Risk | L | I | Mitigation | Owner |
|---|---|---|---|---|---|
| R-01 | **ROS `PYTHONPATH` poisons the project env.** `~/.bashrc` sources ROS Humble, exporting Python 3.10 site-packages that land on a Python 3.11 `sys.path`. *Verified live on this machine.* Pure-Python ROS packages shadow real ones; compiled ones raise opaque ABI errors. | **High** (certain without mitigation) | High | `env.sh` unsets `PYTHONPATH`, filters `/opt/ros/*` from `LD_LIBRARY_PATH`, sets `PYTHONNOUSERSITE=1`. `check_env.py` **fails** if any `ros/humble` entry is on `sys.path`, so a regression is caught on the next run. Python 3.11 chosen partly because `~/.local/lib/python3.11` is empty. | TC-002 (impl), TC-003 (assert) |
| R-02 | **Shared GPU / VRAM contention.** 24 GB is free today only because a 16 GB NaVILA server was stopped with user approval. Other projects on this box routinely park multi-GB servers on GPU 0 and may do so again mid-run. | Medium | Medium | Documented OOM degradation ladder (`ARCHITECTURE.md` §9): `--not_on_device` → lower `-npp/-nps` → `--disable_tta` → `--max-side` downscale → `--device cpu`. `inference.py` detects OOM and prints the ladder as literal next commands instead of a traceback. CPU path always works. **No card may ever kill a GPU process.** | TC-006, TC-008 |
| R-03 | **Predictions are `{0,1}`-valued PNGs, not `{0,255}`.** `NaturalImage2DIO.write_seg` writes raw label values. The files look solid black; the natural reaction is "the model detected nothing" and then "let me rescale the prediction file". | **High** (near-certain to confuse) | Medium | Documented in `ARCHITECTURE.md` §4.3 and `INTERFACES.md` §3.2 with a warning callout. `inference.py` logs the fact once per run. All consumers binarise as `pred > 0`. Viewable renders are separate files in `overlays/`. Smoke test asserts `set(unique) ⊆ {0,1}` so the convention is pinned by a test. | TC-008, TC-009, TC-006 |
| R-04 | **Input format breaks the channel contract.** `NaturalImage2DIO` rejects `.jpg`/`.jpeg` outright (lossy compression is deliberately excluded) and asserts `shape[-1] ∈ {3,4}`; the plans declare exactly 3 channels. RGBA → 4 ch and grayscale → 1 ch both fail. Phone EXIF rotation silently changes orientation. | **High** | High | `prepare_inputs` forces `exif_transpose` → `convert("RGB")` → PNG for *every* input, unconditionally. Unit tests cover RGBA, grayscale/L, palette, CMYK, 16-bit and EXIF-rotated fixtures. | TC-007 |
| R-05 | **Forgetting `-f 0` / `-chk checkpoint_ep0500.pth`.** nnU-Net defaults to folds `(0,1,2,3,4)` and `checkpoint_final.pth`; this model has only fold 0 and no `checkpoint_final.pth`. The failure is a confusing "file not found" deep in nnU-Net. | Medium | Medium | Both are hard-coded from `config/project.yaml` in `inference.py` and are **named acceptance criteria** in TC-008. `verify_model.py` asserts exactly which checkpoint exists. | TC-008, TC-005 |
| R-06 | **Upstream HF repo changes** (file renamed, revision updated, repo gated or removed). The model card prose already disagrees with the repo (`nnUNetPlans.json` vs the actual `plans.json`). | Low | High | `config/model_manifest.json` records every file's size + sha256 + revision. `verify_model.py` validates the tree *and* the semantic contents of `dataset.json`/`plans.json`. A mismatch is a **BLOCKER to report**, never something to patch around. | TC-004, TC-005 |
| R-07 | **Domain mismatch.** OpenCrack is pavement/close-up-surface regime; it over-fires on crack-like texture and on masonry bonds/mortar lines, and collapses on wide scenes (0.142 IoU). D405 imagery at 10–20 cm is *closer* than most training data, at an unusual scale, under LED/indoor lighting. | Medium | **High** (this is the project's core question) | Not mitigated — **measured**. This is the research question, not a defect. Level-3 evaluation deliberately includes negative controls (seams, stains, aggregate, scratches, marker lines, no-crack) and a distance sweep so the failure surface is characterised rather than discovered by accident. | `D405_TEST_PLAN.md`, TC-015 |
| R-08 | **Depth is missing or wrong exactly at the crack.** A crack is a narrow cavity, often narrower than the stereo correlation window, so the D405 returns the surface depth across it, or a 0-valued hole. | **High** | Medium (deferred impact) | Out of scope this phase (`adr/002`), but pre-empted: raw `uint16` depth is preserved losslessly, alignment is done at capture, and per-frame depth scale + intrinsics are stored — so a later stage can fit a local surface plane instead of sampling per-pixel. `D405_TEST_PLAN.md` records depth-hole fraction as a metric to watch. | TC-013 |
| R-09 | **Hard-coding the depth scale.** D405 typically uses 0.0001 m/unit; most other D4xx use 0.001. A hard-coded 0.001 silently makes every future 3D point 10× too far away. | Medium | **High** | `depth_scale_m_per_unit` **must** come from `depth_sensor.get_depth_scale()` and be written into every per-frame JSON. Named acceptance criterion in TC-013; reviewed in TC-014. | TC-013 |
| R-10 | **Model/data artefacts committed to git.** The checkpoint is 268 MB and **git-lfs is not installed** on this machine. A single accidental `git add -A` creates an unpushable repo. | Medium | High | `.gitignore` (TC-001) excludes `models/`, `nnunet/`, `data/**` (except `.gitkeep`), `logs/`. TC-001's acceptance criteria include an explicit test that a file dropped in each of those directories is ignored. Cards commit named paths, never `git add -A`. | TC-001 |
| R-11 | **Disk exhaustion.** Was 42 GB free / 91 % used at inspection. Cleanup during planning took it to 124 GB, but ~20 GB of root-owned Jetson rootfs remains and other projects grow. | Low (post-cleanup) | Medium | Model downloaded with `local_dir` **inside the project** rather than into the already-17 GB HF hub cache. `check_env.py` reports free disk and WARNs below 20 GB. The remaining root-owned 20 GB needs a user-run `sudo rm -rf ~/nvidia/nvidia_sdk` — **not** a task card. | TC-003, TC-004 |
| R-12 | **`pyrealsense2` install or import failure** blocks segmentation work. | Medium | Low | Installed from a **separate** `requirements-realsense.txt`, never part of the core install. All RealSense imports are lazy and guarded. `crackvision.realsense_capture` imports fine, and its tests pass, with no `pyrealsense2` present. | TC-002, TC-012, TC-013 |
| R-13 | **No D405 attached** (confirmed by `lsusb`), so camera code cannot be validated against hardware. | **High** (true today) | Medium | Every camera path is hardware-optional: `--list-devices`, `--dry-run`, `--synthetic`. `check_realsense.py` exits **0** with zero devices (WARN, not FAIL). A 16-bit PNG round-trip unit test proves depth fidelity with no camera. TC-013's acceptance criteria are fully satisfiable headless; hardware verification is an explicitly-labelled deferred step. | TC-012, TC-013 |
| R-14 | **Frame-invariant violation.** Any resize/crop/pad between original, mask, skeleton and aligned depth silently breaks future 3D projection — and it breaks *quietly*, surfacing months later as a mis-registered trajectory. | Medium | **High** | Stated normatively (`INTERFACES.md` §0.5). `visualize` hard-errors on a shape mismatch between prediction and original. The smoke test asserts `prediction.shape == input.shape`. `--max-side` is off by default and records its factor in `case_map.json`. | TC-007, TC-009, TC-006, TC-014 |
| R-15 | **Hard-coded machine paths** (`/home/boosterk1/...`) leak into source, breaking reproducibility on the capstone's other machines. | Medium | Medium | All paths resolve from `CRACKVISION_ROOT` / `config/project.yaml`; `case_map.json` and manifests store **project-relative POSIX** paths. TC-014 adds a repo-wide grep test that fails on any literal `/home/` in `src/`, `scripts/`, `tools/`, `tests/`. | TC-014 |
| R-16 | **Dependency resolution churn.** `nnunetv2` pins `torch>=2.1.2,!=2.9.*` and pulls a wide tree (batchgenerators, blosc2, acvl-utils, dynamic-network-architectures, SimpleITK…). A later `pip install` could silently swap the CUDA torch for a CPU wheel from PyPI. | Medium | High | Install order is fixed: CUDA torch from the cu126 index **first**, then `nnunetv2`. TC-002 re-asserts `torch.cuda.is_available()` and that `torch.__version__` still carries `+cu` **after** every install step. `requirements-core.txt` is pinned from `pip freeze` once green. | TC-002 |
| R-17 | **Model licence obligations ignored.** OpenCrack is CC-BY-4.0; nnU-Net is Apache-2.0. A capstone report that omits attribution is a real compliance problem. | Medium | Medium | `fetch_model.py` logs the licence on every run. The README carries the attribution block (Fadeev 2026 + Isensee et al. 2021) and TC-016 verifies it is present. | TC-004, TC-016 |
| R-18 | **Scope creep by implementation agents** — adding skeleton graph traversal, depth projection, a ROS node, or a fine-tune "while they're in there". | **High** (LLM agents default to helpfulness) | Medium | Every card has an explicit **Out of scope** section. `AGENT_INSTRUCTIONS.md` rules 5–7 forbid it. `adr/008`, `adr/009`, `adr/010` record the decisions so they are not relitigated. The completion report format forces the agent to declare what it changed. | All cards |
| R-19 | **RAM/CPU exhaustion from nnU-Net worker processes.** Only 12 logical CPUs; `-npp`/`-nps` spawn workers that each hold decoded images. | Low | Medium | Defaults stay at 3/3 and cards must not raise them. `--npp/--nps` exposed for tuning downward. 62 GB RAM gives headroom. | TC-008 |
| R-20 | **Sequential-card drift** — a later agent works from stale assumptions because an earlier card deviated. | Medium | Medium | `docs/COMPLETION_LOG.md` is append-only and every card must append its completion report; `AGENT_INSTRUCTIONS.md` rule 4 requires reading prerequisite reports before starting. `TASK_INDEX.md` carries live status. | All cards |

## Risks explicitly accepted (no mitigation planned)

- **Single-fold, 500-epoch checkpoint** is a lower ceiling than a 5-fold ensemble. Accepted (`adr/001`).
- **No quantitative accuracy evaluation this phase.** Level 2 proves execution, not quality. Accepted
  (`VALIDATION_PLAN.md`).
- **Python 3.11 cannot import this box's `rclpy`.** Accepted; ROS is deferred (`adr/009`).
- **`~/nvidia/nvidia_sdk` root-owned remnant (~20 GB)** requires interactive `sudo`; left to the user.
